# 스트림 · 메시지 버퍼, 공유 메모리

바이트를 이어서 흘려보내는 통로(스트림), 보낸 단위를 지켜 주는 통로(메시지), 같은 메모리를 함께 쓰는 방법(공유 메모리)

보내는 쪽이 `"HEL"` · `"LO\nWO"` · `"RLD\n"`을 3번에 나눠 보내고, 받는 쪽은 10ms 늦게 읽음.

| 예제 | Linux (프로세스끼리) | FreeRTOS (태스크끼리) |
|---|---|---|
| 스트림 | 파이프. 한 번에 12바이트로 받음 → `'\n'`으로 다시 나눠 2줄 | 스트림 버퍼. 같음 |
| 메시지 | `socketpair(AF_UNIX, SOCK_DGRAM)`. 3번에 3 · 5 · 4바이트 | 메시지 버퍼. 같음. 메시지마다 길이(`size_t`)가 함께 저장됨 |
| 트리거 레벨 | | 4로 두면 1바이트씩 쓰는 동안 4바이트가 모인 8ms에 처음 깨어남 |
| 공유 메모리 | `shm_open` + `mmap`. 두 프로세스가 20만 번씩 더하면 잠금 없이는 값이 사라지고, 이름 있는 세마포어로 잠그면 400000 | 주소 공간이 하나라 전역 변수가 곧 공유 메모리. 보호는 뮤텍스(11장) |

## 실행

```bash
cmake --preset posix && cmake --build --preset posix
./build/posix/chapters/stream-buffer/stream-buffer-linux
./build/posix/chapters/stream-buffer/stream-buffer-freertos
```

## 포인트

- 스트림은 경계가 없음. 받는 쪽이 `'\n'`이나 길이 필드로 직접 나눠야 함 (UART · TCP와 같음)
- 메시지 버퍼는 메시지마다 길이를 함께 저장해서 공간을 더 씀. 64비트 PC는 8바이트, Cortex-M은 4바이트. FreeRTOS 예제의 버퍼를 32바이트로 줄이면 세 번째 메시지가 안 들어가서 보내는 쪽이 멈춤
- 트리거 레벨을 1로 바꾸면 첫 바이트가 들어온 2ms에 바로 깨어남. 크게 잡으면 깨어나는 횟수가 줄지만 반응이 늦어짐
- FreeRTOS 스트림 · 메시지 버퍼는 보내는 쪽 하나, 받는 쪽 하나를 전제로 함. 여럿이면 잠금이 필요
- 공유 메모리는 가장 빠르지만 규칙(잠금)을 직접 지켜야 함. 프로세스끼리는 프로세스 사이에서도 통하는 잠금(이름 있는 세마포어 등)을 씀
