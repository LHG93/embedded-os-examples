# 뮤텍스

여러 변수를 한 묶음으로 바꿔야 할 때, 그 묶음을 한 태스크만 다루게 잠그는 도구

계좌 a, b (각 1000)에서 서로 1씩 옮김. 합계 a + b는 언제 봐도 2000이어야 함. 검사하는 쪽이 옮기는 도중의 합계를 계속 읽어서 2000이 아닌 순간을 셈.

| 방법 | Linux (스레드 2 × 100만 번) | FreeRTOS (태스크 2 × 1000번) |
|---|---|---|
| 잠금 없이 | 최종 합계부터 틀림 | 최종 합계부터 틀림 |
| 변수마다 원자 연산 · 임계 구역 | 최종 합계는 2000, 도중에 틀린 합계가 수백만 번 보임 | 최종 합계는 2000, 도중에 틀린 합계 약 1400번 |
| 뮤텍스 (검사도 잠금) | 2000, 틀린 순간 0번 | 2000, 틀린 순간 0번 |

## 실행

```bash
cmake --preset posix && cmake --build --preset posix
./build/posix/chapters/mutex/mutex-linux
./build/posix/chapters/mutex/mutex-freertos
```

## 포인트

- 원자 연산 · 임계 구역은 변수 하나를 지킴. 변수 여러 개를 한 번에 바꾸는 동안의 중간 상태는 못 막음
- 읽는 쪽도 잠가야 함. Linux 예제의 `m_total()`에서 잠금을 빼면, 쓰는 쪽이 잠가도 틀린 합계가 다시 보임 (macOS에서 14만 ~ 25만 번)
- 뮤텍스를 풀지 않고 끝내면 기다리던 태스크가 영원히 멈춤. FreeRTOS 예제의 `give()`를 비우면 뮤텍스 단계에서 멈춰서 `run_all.sh`의 20초 제한에 걸림
- FreeRTOS 뮤텍스는 잠근 태스크만 풀 수 있고, 우선순위 상속이 있음. ISR에서는 못 씀
- 잠근 동안 기다리는 함수(`vTaskDelay` 등)를 불러도 됨. 기다리는 건 같은 뮤텍스를 쓰려는 태스크뿐, 다른 태스크 · 인터럽트는 계속 돎
