# 워치독

정해진 시간 안에 "살아 있음" 신호(킥)가 없으면 시스템을 리셋하는 하드웨어 타이머. 소프트웨어가 멈췄을 때의 마지막 안전망

## FreeRTOS on Cortex-M3 (qemu-mps2 전용)

CMSDK 워치독, 제한 100ms. 0이 되면 NMI로 경고, 한 번 더 0이 되면 리셋. 태스크 A · B가 50ms마다 체크인하고, 감시 태스크는 **둘 다 체크인했을 때만** 킥

```text
부팅
정상 500ms           : 킥 10번, 워치독 경고 0번
B가 멈춤             : 무한 루프에 빠짐
감시 태스크          : B 체크인 없음 → 킥을 멈춤
[워치독 경고] 킥 없이 100ms 지남 (B 마지막 체크인 뒤 150ms) → 100ms 뒤 리셋
```

`run_qemu.sh`는 `-no-reboot`라서 리셋되면 QEMU가 끝남. 이 옵션을 빼고 실행하면 리셋 뒤 다시 "부팅"부터 반복

```bash
cmake --preset qemu-mps2 && cmake --build --preset qemu-mps2 --target watchdog-freertos
./scripts/run_qemu.sh build/qemu-mps2/chapters/watchdog/watchdog-freertos.elf
```

## Linux (사용자 공간)

하드웨어 워치독(`/dev/watchdog`)은 보통 systemd가 킥하고, 컨테이너에서는 못 씀. 같은 구조를 프로세스 안에서 만듦

- 작업 스레드 A · B가 50ms마다 시각을 남기고, 감시 스레드가 150ms 넘게 소식이 없으면 종료 코드 2로 끝냄
- 감독(부모) 프로세스가 비정상 종료를 보고 다시 띄움 (systemd `Restart=on-failure`와 같음)

```text
감독: 1번째 실행
  감시 스레드: B가 155ms 동안 소식 없음 → 프로세스 종료(2)
감독: 종료 코드 2 → 다시 시작
감독: 2번째 실행
  500ms 정상
결과: 다시 시작 1번, 마지막 종료 코드 0
```

## 포인트

- 킥은 "모든 중요한 태스크가 살아 있을 때만". 타이머 인터럽트 등에서 무조건 킥하면 태스크가 멈춰도 리셋되지 않음 (감시 태스크를 무조건 킥으로 바꾸면 B가 멈춘 채 20초 동안 그대로)
- 경고(NMI)에서는 커널 API를 못 씀. 원인 기록만 남기고 리셋을 기다림
- 제한 시간은 정상일 때 가장 오래 걸리는 주기보다 넉넉하게, 멈춤을 알아채야 하는 시간보다는 짧게
- AUTOSAR는 WdgM(워치독 관리자)이 런너블마다 살아 있음 · 순서 · 기한을 감시하고, WdgIf · Wdg 드라이버로 하드웨어를 킥
